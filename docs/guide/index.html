Overview概览

Virtuoso Bridge lets AI agents drive Cadence Virtuoso and Spectre, locally or on a remote server, through Python, SKILL or the command line.Virtuoso Bridge 让 AI 智能体通过 Python、SKILL 或命令行操作 Cadence Virtuoso 与 Spectre，可以在本机，也可以在远程服务器上。

Lite by default. Spectre execution and PDK/CDF callbacks are the core, for GUI-equivalent electrical results with matching netlists, models and options. Common schematic, symbol and GDS operations get lightweight wrappers; anything else goes through raw SKILL. Multi-server, multi-account and process configuration are optional, never a prerequisite for the one-host workflow.默认轻量。核心是 Spectre 执行与 PDK/CDF 回调，保证网表、模型和选项一致时得到与 GUI 相同的电学结果。常用的原理图、符号和 GDS 操作有轻量封装，其余都可以直接写 SKILL。多服务器、多账号与工艺配置都是可选项，单主机的常规用法不需要它们。

  • Run inline SKILL, load .il files, or use the Python APIs.执行内联 SKILL、加载 .il 文件，或使用 Python API。
  • Four design domains: schematic editing, layout generation, Maestro simulation setup, and standalone Spectre with PSF ASCII parsing.四个设计领域：原理图编辑、版图生成、Maestro 仿真设置，以及解析 PSF ASCII 结果的独立 Spectre。
  • Deterministic schematic planning: explicit connectivity plus grid, polarity-row, differential-pair, pin-column and output-stage constraints.确定性的原理图规划：显式连接关系，加上网格、极性行、差分对、引脚列和输出级约束。
  • Exact schematic recreation across PDKs through explicit process maps, symbol-pin audits, readback checks and GUI screenshots.跨 PDK 精确复现原理图：显式工艺映射、符号引脚核对、回读校验和 GUI 截图。
  • Optional SOS cellview control: status, checkout, cancel, checkin and registration, with dry runs and post-state checks.可选的 SOS cellview 管理：状态、检出、取消检出、检入和注册，支持试运行与结果核对。
  • Optional scale-out: several design servers, each with its own tunnel, and parallel simulations across servers and accounts.可选的横向扩展：连接多台设计服务器，各自独立隧道，并可跨服务器和账号并行仿真。
  • Built for coding agents: CLI-first lifecycle (start / status / restart), agent skill files in skills/, and role-aware SSH routing.为编程智能体设计：命令行优先的生命周期（start / status / restart）、skills/ 里的智能体技能文件，以及按角色区分的 SSH 路由。
  • Client on macOS, Windows and Linux (CI covers Linux and Windows); the Virtuoso side runs on Linux.客户端支持 macOS、Windows 和 Linux（CI 覆盖 Linux 与 Windows）；Virtuoso 端运行在 Linux 上。

How it compares with skillbridge: see the table on the home page.与 skillbridge 的区别见首页的对比表。

Install and connect安装与连接

macOS · Linux
# 0. Get the source
git clone https://github.com/Arcadia-1/virtuoso-bridge-lite.git
cd virtuoso-bridge-lite

# 1. Install in a virtual environment
uv venv .venv
source .venv/bin/activate
uv pip install -e .

# 2. Create ~/.virtuoso-bridge/.env
virtuoso-bridge init user@host [-J user@jump-host]
# or: virtuoso-bridge init   (empty template; set VB_REMOTE_HOST yourself)

# 3. Start and verify
virtuoso-bridge start     # prepare fixed-port setup and tunnel
# Load the printed setup in the intended idle CIW, then:
virtuoso-bridge start
virtuoso-bridge status    # signed daemon status and Spectre availability

On Windows PowerShell, activate with .\.venv\Scripts\Activate.ps1. Default start prepares the fixed-port setup and tunnel. Load its printed load(...) line in the intended idle CIW, then check status.Windows PowerShell 下用 .\.venv\Scripts\Activate.ps1 激活。默认 start 准备固定端口 setup 和隧道。在目标空闲 CIW 中加载打印的 load(...)，然后检查状态。

Optional X11 bootstrap: pick one top-level CIW explicitly and inject only the generated setup command. bootstrap refuses windows that are not a CIW and never accepts arbitrary SKILL.可选的 X11 自动加载：先明确选定一个顶层 CIW，只注入生成的 setup 命令。bootstrap 会拒绝不是 CIW 的窗口，也不接受任意 SKILL。

shell
virtuoso-bridge list-windows --top-level --json
virtuoso-bridge bootstrap --window 0x3000012

Legacy fixed-port mode remains the default. Set VB_AUTO_SESSIONS=1 explicitly for directory-based discovery and OS-assigned ports. A working directory alone does not enable discovery. Configured fixed ports and saved identities never silently migrate to another instance. See the compatibility note.默认保留旧固定端口模式。显式设置 VB_AUTO_SESSIONS=1 才启用按目录发现实例及系统分配端口。仅设置工作目录不会开启发现。固定端口和保存的实例身份不会静默迁移到另一个实例。参见兼容性说明。

Local mode本机模式

Automatic local discovery requires Linux. When Virtuoso runs on that same machine, set VB_REMOTE_HOST=localhost: no SSH, and the setup uses the local Python. Details: connection guide.自动发现的本机模式要求 Linux。Virtuoso 在该机器运行时设置 VB_REMOTE_HOST=localhost：不走 SSH，setup 使用本机 Python。详见 connection guide。

Which .env is used使用哪个 .env

Python entry points load the nearest parent .env that sets a bridge host role (VB_REMOTE_HOST, VB_GUI_HOST, VB_DAEMON_HOST…) or VB_LOCAL_PORT, with override=True. That can switch a long-lived process between local and remote mode, so pin the file before creating a client when you embed the bridge:Python 入口会加载最近的上级目录中设置了桥接主机角色（VB_REMOTE_HOST、VB_GUI_HOST、VB_DAEMON_HOST…）或 VB_LOCAL_PORT 的 .env，并且 override=True。这可能让长期运行的进程在本机/远程模式之间切换，所以嵌入使用时先固定文件再创建客户端：

python
from virtuoso_bridge.env import set_runtime_env_file

set_runtime_env_file("/path/to/virtuoso-bridge.env")

Run SKILL执行 SKILL

python
from virtuoso_bridge import VirtuosoClient

client = VirtuosoClient.from_env()
client.execute_skill("1+2")  # VirtuosoResult(status=SUCCESS, output='3')

Or skip Python and run SKILL from the shell:也可以不写 Python，直接在命令行执行 SKILL：

shell
# One-liner: full VirtuosoResult JSON on stdout
virtuoso-bridge eval 'getCurrentTime()'

# Multi-line SKILL via heredoc (wrapped in progn; returns the last form)
virtuoso-bridge eval --stdin <<'EOF'
let((libs)
  libs = mapcar(lambda((l) l~>name) ddGetLibList())
  printf("found %d libraries\n" length(libs))
  libs)
EOF

# Whole .il file, uploaded automatically in SSH mode
virtuoso-bridge load my_script.il

Schematic, layout and Spectre原理图、版图与 Spectre

Operation-scoped schematic diagnostics: only messages from this schCheck/dbSave, with a blocking modal reported separately instead of stale CIW history.只针对本次操作的原理图诊断：只收集这次 schCheck/dbSave 的消息，阻塞弹窗单独报告，不混入旧的 CIW 历史。

python
report = client.schematic.check_and_save("myLib", "myCell")
print(report.status, report.check_error_count, report.check_warning_count)
for diagnostic in report.diagnostics:
    print(diagnostic.severity, diagnostic.code, diagnostic.message)

Recreate existing drawings across PDKs with the exact-coordinate manifest workflow; it never guesses devices or placement. JSON contracts and a runner: examples/01_virtuoso/schematic_manifest.用精确坐标的 manifest 流程在多个 PDK 上复现已有原理图，不会猜测器件或摆放。JSON 约定和完整脚本见 examples/01_virtuoso/schematic_manifest。

python
result = client.schematic.import_manifest(
    "source.json",
    "process-map.json",
    processes=["pdk180", "pdk28"],
)
client.schematic.capture_import_result(result, "output/evidence")

Standalone Spectre with strict PSF ASCII helpers, so missing files, keys or shapes fail fast instead of being guessed:独立 Spectre 与严格的 PSF ASCII 读取函数：文件、键名或数据形状不对时直接报错，不做猜测：

python
from pathlib import Path
from virtuoso_bridge.spectre import SpectreSimulator
from virtuoso_bridge.spectre.psf import frequency_hz, read_psf_ascii, result_file, vector

result = SpectreSimulator.from_env(work_dir="output").run_simulation("tb.scs")
if not result.ok:
    raise RuntimeError(result.errors)
raw_psf = Path(result.metadata["output_dir"])
ac = read_psf_ascii(result_file(raw_psf, "*.ac"))
frequency = frequency_hz(ac)
vout = vector(ac, "VOUT")  # exact raw PSF key; missing or invalid data raises

Maestro snapshotsMaestro 快照

Pull the focused Maestro session's setup and latest-run artifacts into a local folder:把当前聚焦的 Maestro 会话的设置和最近一次运行的产物拉到本地目录：

shell
virtuoso-bridge snapshot -o output                              # newest history
virtuoso-bridge snapshot -o output --history Interactive.160    # a specific history
output/
output/20260422_142137__MyLib__myTB/
├── maestro.sdb, active.state                        raw Cadence files
├── state_from_sdb.xml, state_from_active_state.xml  filtered, high-signal
├── state_from_skill.txt                             SKILL-probe setup summary
└── Interactive.N/
    ├── Interactive.N.{log,rdb,msg.db}               run level (rdb = SQLite)
    └── <pt>/<tb>/
        ├── netlist/   netlist, input.scs, qpInformation.ils, exprOutputs.json, paramInfo.ils
        └── psf/       spectre.out, logFile, dcOp.dc, *.ac, *.tran, ...

Each point keeps the five netlist files that describe the runnable design, plus stdout, logs and non-binary results. The rules live in snapshot_filter.yaml; comment lines in or out to change them. Binary waveforms are never pulled; read scalar results with client.maestro.read_results().每个点只保留描述可运行设计的 5 个网表文件，以及 stdout、日志和非二进制结果。规则在 snapshot_filter.yaml 里，注释或取消注释即可调整。二进制波形不会拉取，标量结果用 client.maestro.read_results() 读取。

Shared CIW共享 CIW

When people also use the CIW, opt into client.dialogs.enable_guard(protect_inflight=True) with an upgraded daemon. A request that meets a popup returns a recovery handle instead of interrupting Virtuoso or retrying; after the user resolves the popup, read the original result with client.requests.receipt(handle). This mode is off by default.有人同时在用 CIW 时，配合新版 daemon 开启 client.dialogs.enable_guard(protect_inflight=True)。遇到弹窗的请求会返回一个恢复句柄，不会打断 Virtuoso，也不会自动重试；用户处理完弹窗后，用 client.requests.receipt(handle) 取回原请求的结果。此模式默认关闭。

Closing an informational popup is also opt-in: a single-use visual approval bound to the exact CIW and window, with no automatic key injection or forced close.关闭提示类弹窗同样需要显式开启：一次性的可视化确认，绑定到具体的 CIW 和窗口，不会自动注入按键或强制关闭。

Requirements and limits: shared CIW dialogs.部署要求与限制见 shared CIW dialogs。

Configuration配置

Remote scratch远端工作目录

The stock scratch parent is /tmp. Workflow paths retain virtuoso_bridge_<user>/<client>/<leaf>. Default records and generated bootstrap use the private /tmp/virtuoso_bridge_<user> child. Explicit private roots remain supported through VB_REMOTE_SCRATCH_ROOT.临时文件父目录恢复为 /tmp，工作流路径保留 virtuoso_bridge_<user>/<client>/<leaf>。默认实例记录和生成的启动文件使用私有子目录 /tmp/virtuoso_bridge_<user>。仍可通过 VB_REMOTE_SCRATCH_ROOT 指定私有根目录。

Records live in runs/, and the shared bootstrap in daemon/. Client work directories retain their client ID. Deployment and CIW hosts must see the same files; changing the root does not move a loaded daemon.实例记录位于 runs/，共用启动文件位于 daemon/。客户端工作目录仍按客户端 ID 隔离。部署主机与 CIW 必须能访问相同文件；修改根目录不会迁移已加载的 daemon。

Use absolute paths for remote workflow staging; the registry helper alone expands ~/ on the daemon host. Generated setup embeds the registry root. Shared setup uses installer --scratch-root, then daemon RB_SCRATCH_ROOT, then VB_REMOTE_SCRATCH_ROOT, then the default private child. Client edits do not update a loaded CIW. Never chmod a shared parent; existing artifacts remain in place.远程工作流暂存目录应使用绝对路径；只有注册表助手在 daemon 主机上展开 ~/。生成的 setup 写入注册表根目录。共享 setup 优先使用安装器的 --scratch-root，然后依次使用 daemon 的 RB_SCRATCH_ROOT、VB_REMOTE_SCRATCH_ROOT 和默认私有子目录。修改客户端设置不会更新已经加载的 CIW。不要修改公共父目录权限；现有产物保留原位。

Token generation uses the original home-based path and configured overrides. Registered clients still require a signed handshake matching the selected record. Shared-account processes share that trust boundary; project filters prevent mistakes, not access by the same UID. Private record files alone do not authenticate an endpoint. Windows clients rely on Windows ACLs for local state. Daemon installation and local discovery require Linux; Windows/macOS clients can connect over SSH.令牌生成恢复使用原有主目录路径及配置的覆盖选项。注册实例客户端仍要求签名握手与所选记录一致。同账号进程共享信任边界；项目过滤只能减少误操作，不能阻止相同 UID 的访问。私有记录文件本身不能认证端点。Windows 客户端依靠 Windows ACL 保护本地状态。daemon 安装和本机发现要求 Linux；Windows/macOS 客户端可经 SSH 连接。

Install, select and upgrade安装、选择与升级

Prepare the Linux Cadence host and an absolute Python interpreter, then have a trusted installer create a new protected bundle. All accounts loading its code trust the installer UID. Ancestors must be real directories owned by root or that UID, without group/other write permission. Existing bundles are never overwritten; use a new versioned path for upgrades.先准备 Linux Cadence 主机和 Python 解释器的绝对路径，再由可信安装账号创建受保护的新版本目录。加载代码的账号都信任安装者 UID。上级目录必须是真实目录，属主为 root 或安装者，且组和其他用户不可写。安装器不会覆盖已有版本；升级请使用新目录。

virtuoso-bridge install-daemon /opt/virtuoso-bridge/v2 --python /usr/bin/python3
# Put the printed load(...) line in the project's .cdsinit.
# Client .env:
VB_AUTO_SESSIONS=1
VB_DAEMON_SETUP=/opt/virtuoso-bridge/v2/virtuoso_setup.il
VB_REMOTE_WORK_DIR=/projects/example
# Then:
virtuoso-bridge sessions --json
virtuoso-bridge start --port 65123
virtuoso-bridge status --port 65123

With automatic sessions enabled, the project directory filters candidates independently of the deployment root. Both CLI --port and VB_REMOTE_PORT constrain the endpoint. Multiple matches or an expired saved identity require explicit selection. Selection does not alter allocation requests. sessions is read-only.开启自动会话后，项目目录用于筛选实例，与部署根目录无关。CLI --port 和 VB_REMOTE_PORT 都精确限定端点。存在多个匹配或保存的身份失效时，必须显式选择。选择实例不会修改端口分配请求。sessions 只读。

In automatic mode without a shared setup, start prepares <root>/daemon/virtuoso_setup.il when no instance is available. Explicit X11 bootstrap needs that existing file or VB_DAEMON_SETUP. A vanished saved instance requires explicit reselection, including within the same project. Uncertain work is never replayed. Retained tunnels are listed; use stop --port PORT through the original configuration. Inspect suspect saved processes before stopping them.自动模式未配置共享 setup 且无可用实例时，start 准备 <root>/daemon/virtuoso_setup.il。显式 X11 加载需要此文件已存在，或设置 VB_DAEMON_SETUP。保存的实例消失后，即使在同一项目内也需要显式重新选择。结果不确定的工作不会重放。保留的隧道会列出；通过原配置执行 stop --port PORT。停止前应检查可疑的历史进程。

Default legacy connections do not consult the registry. Automatic bootstraps require explicit loading in the intended idle CIW. Private deployment and registry roots require the current account as owner and mode 0700; records require mode 0600. Unsafe ancestors and foreign-owned paths are rejected, and file operations stay anchored to verified descriptors. Shared code uses a separately protected installer-owned directory. Cadence lifecycle verification is separate from offline tests.默认旧模式连接不查询注册表。自动启动文件必须在目标空闲 CIW 中显式加载。私有部署和注册目录要求当前账号为属主且权限为 0700，记录文件为 0600。拒绝不安全的祖先目录及其他账号拥有的路径，文件操作锚定已验证的目录描述符。共享代码使用单独受保护的安装者目录。Cadence 生命周期验证与离线测试分开记录。

Choose a fixed daemon port指定 daemon 固定端口

For default legacy mode, set VB_REMOTE_PORT, run start, and load its printed setup. For an opt-in registered daemon, install a shared bootstrap and choose a fixed port using a persistent request or variables set before loading. Client VB_REMOTE_PORT selects the endpoint; it does not reconfigure a running daemon.默认旧模式下，设置 VB_REMOTE_PORT，运行 start，再加载打印的 setup。对于显式开启的注册 daemon，可安装共享启动文件，并通过持久请求或加载前设置变量指定固定端口。客户端 VB_REMOTE_PORT 选择端点，不会重新配置运行中的 daemon。

For a persistent request, run as the Virtuoso account on the daemon host. Use the same scratch root on the daemon and client. Omit --port to clear the request; omit --work-dir for an account-wide request. Directory requests take precedence. The allocation token is separate from the authentication token.持久请求需在 daemon 主机上以 Virtuoso 账号设置，daemon 与客户端使用相同的 scratch root。省略 --port 可清除请求，省略 --work-dir 则设置账号级请求；目录级请求优先。这种端口请求文件与认证令牌不同。

/usr/bin/python3 /opt/virtuoso-bridge/v2/ramic_registry.py --scratch-root /home/user/.virtuoso-bridge --configure --work-dir /projects/example --port 65123

Alternatively, with a newly generated setup, put these lines in the intended CIW or project .cdsinit before the daemon starts:也可以使用新生成的 setup，在 daemon 启动前将以下内容放入目标 CIW 或项目 .cdsinit：

setShellEnvVar("RB_PORT" "65123")
load("/opt/virtuoso-bridge/v2/virtuoso_setup.il")

The setup preserves RB_PORT and enables instance registration. A nonzero value overrides request files; "0" consults directory/account requests, then uses OS allocation. Older setup files overwrite this variable; install a new bundle first. Variables belong to the Virtuoso process, not the client dotenv file. An occupied requested port fails. Neither method changes a running child; RBSetPort(N) switches an idle instance.setup 保留 RB_PORT 并启用实例注册。非零值优先于请求文件；设为 "0" 时先查目录级和账号级请求，再由系统分配。旧 setup 会覆盖该变量，需先安装新版本。这些变量属于 Virtuoso 进程，不是客户端 dotenv 配置。请求的端口被占用时会失败。两种方法都不会直接改变运行中的子进程；空闲实例可用 RBSetPort(N) 切换。

# Client .env (registered mode; match the daemon scratch root):
VB_AUTO_SESSIONS=1
VB_REMOTE_PORT=65123
VB_REMOTE_SCRATCH_ROOT=/home/user/.virtuoso-bridge
# After the CIW reports the port is listening:
virtuoso-bridge start --port 65123
virtuoso-bridge status --port 65123

Split GUI and daemon hostsGUI 与 daemon 分机部署

VB_REMOTE_HOST stays the simple one-host setting. Where Virtuoso runs on a GUI/login host but ipcBeginProcess() starts the daemon on a compute host, set the roles explicitly:VB_REMOTE_HOST 仍是最简单的单主机设置。如果 Virtuoso 跑在 GUI/登录主机上，而 ipcBeginProcess() 把 daemon 启动在计算主机上，就显式配置各角色：

.env
VB_GUI_HOST=gui-host-a
VB_DEPLOY_HOST=gui-host-a
VB_DAEMON_HOST=compute-host-b
VB_SPECTRE_HOST=compute-host-b
VB_REMOTE_USER=user
VB_JUMP_HOST=gui-host-a

# Must be readable from the CIW and daemon host; /tmp is often isolated.
VB_REMOTE_SCRATCH_ROOT=/home/user/.virtuoso-bridge

Defaults: deployment follows the GUI host, Spectre follows the legacy/daemon host, and a target that is itself the jump host skips that jump. status reports these roles and endpoints, compares the complete discovery record with a signed daemon reply, and sends no SKILL. Automatic mode has no legacy CIW banner identity file. Spectre diagnostics still run after discovery failure; unverified bridge status remains nonzero.默认：部署主机跟随 GUI 主机，Spectre 跟随旧版/daemon 主机；目标本身就是跳板机时跳过跳板。status 显示主机角色和端点，将完整实例记录与 daemon 的签名回复比较，不发送 SKILL。自动模式不生成旧版 CIW 横幅身份文件。发现失败后仍检查 Spectre；桥接未验证时返回非零状态。

Daemon network accessdaemon 的网络访问

The daemon listens on 127.0.0.1; SSH tunnels and local mode both reach it through loopback. Only if clients connect over the network (VPN or LAN, no tunnel), set VB_DAEMON_LISTEN_ALL=1 in the .env to listen on all interfaces. Requests stay token-signed either way.daemon 只监听 127.0.0.1，SSH 隧道和本机模式都经回环地址访问。只有客户端经网络直连（VPN 或局域网、不走隧道）时，才在 .env 里设置 VB_DAEMON_LISTEN_ALL=1 监听所有网卡。无论哪种方式，请求都带令牌签名。

IPC loggingIPC 日志

Off by default. Set RB_LOG_ENABLED=1 in the environment that launches Virtuoso; RB_LOG_PATH optionally picks the file (default ramic-bridge.log in Virtuoso's working directory). These are Virtuoso-process variables, not .env settings, and do not change a running Virtuoso. The monitor's logging toggle uses the configured path and restarts only the daemon.默认关闭。在启动 Virtuoso 的环境里设置 RB_LOG_ENABLED=1；RB_LOG_PATH 可指定文件（默认是 Virtuoso 工作目录下的 ramic-bridge.log）。这些是 Virtuoso 进程的环境变量，不是 .env 设置，改了也不影响已运行的 Virtuoso。监视窗口里的日志开关使用已配置的路径，只重启 daemon。

Replay cache size防重放缓存大小

The daemon remembers signed request nonces to reject replays: 4096 by default, and when full it rejects new requests rather than forgetting live entries. For sustained high request rates set, for example, RB_NONCE_CACHE_MAX=8192 where Virtuoso is launched, then restart Virtuoso and the daemon.daemon 记住已签名请求的 nonce 以拒绝重放：默认容量 4096，满了会拒绝新请求，而不是丢弃仍有效的记录。持续高频请求时，在启动 Virtuoso 的环境里设置例如 RB_NONCE_CACHE_MAX=8192，然后重启 Virtuoso 和 daemon。

SSH concurrency with Paramiko用 Paramiko 复用 SSH 连接

OpenSSH ControlMaster does not work with every Windows SSH build. For real multiplexing inside one bridge process, install the Paramiko backend and select it:并非所有 Windows 版 SSH 都支持 OpenSSH ControlMaster。要在一个桥接进程内真正复用连接，安装并选用 Paramiko 后端：

shell
uv pip install -e '.[ssh]'
.env
VB_SSH_BACKEND=paramiko
VB_SSH_MAX_SESSIONS=10
# Optional: route the first SSH hop through an unauthenticated SOCKS5 proxy.
VB_SSH_PROXY=socks5://127.0.0.1:10800

Commands and file transfers then share one authenticated SSH transport, one channel per operation. VB_SSH_MAX_SESSIONS is a client-side gate and must not exceed the server's MaxSessions; extra work waits at the gate. There is no automatic fallback to separate connections. The long-lived tunnel from virtuoso-bridge start stays a standalone OpenSSH process.之后命令和文件传输共用一条已认证的 SSH 连接，每个操作开一个通道。VB_SSH_MAX_SESSIONS 是客户端限流，不能超过服务器的 MaxSessions；超出的任务会排队。不会自动退回多条独立连接。virtuoso-bridge start 建立的长期隧道仍是独立的 OpenSSH 进程。

VB_SSH_PROXY (a socks5://host:port URL without credentials) applies only to Paramiko commands and transfers, not to the OpenSSH tunnel; if the tunnel also needs SOCKS5, configure an OpenSSH ProxyCommand. Proxy failures are reported, never bypassed.VB_SSH_PROXY（不带凭据的 socks5://host:port）只作用于 Paramiko 的命令和传输，不影响 OpenSSH 隧道；隧道也要走 SOCKS5 的话，请配置 OpenSSH ProxyCommand。代理失败会直接报错，不会绕过。

Paramiko reads VB_SSH_CONFIG or the normal SSH config files (Include, aliases, HostName/User/Port, IdentityFile, IdentitiesOnly, one ProxyJump hop). ProxyCommand, chained ProxyJump and revoked-key files fail at start-up instead of being ignored. Host keys must already be in known_hosts: run ssh <host> echo ok once with OpenSSH first.Paramiko 读取 VB_SSH_CONFIG 或常规 SSH 配置（Include、别名、HostName/User/Port、IdentityFile、IdentitiesOnly、一跳 ProxyJump）。ProxyCommand、多跳 ProxyJump 和吊销密钥文件会在启动时报错，不会被悄悄忽略。主机密钥必须已在 known_hosts 中：先用 OpenSSH 执行一次 ssh <host> echo ok。

Architecture架构

  • VirtuosoClient: a plain TCP SKILL client. Sends SKILL as JSON and gets results; it knows nothing about SSH.VirtuosoClient：纯 TCP 的 SKILL 客户端，以 JSON 发送 SKILL 并取回结果，不关心 SSH。
  • SpectreSimulator: runs standalone Spectre locally or over SSH and parses PSF ASCII results into Python data.SpectreSimulator：在本机或经 SSH 运行独立 Spectre，把 PSF ASCII 结果解析成 Python 数据。
  • SSHClient: resolves the GUI, deployment, daemon and Spectre host roles, keeps a standalone port forward to the daemon host, and runs role-specific commands and transfers over OpenSSH or Paramiko. Skipped in local mode.SSHClient：解析 GUI、部署、daemon、Spectre 各主机角色，维持到 daemon 主机的独立端口转发，并通过 OpenSSH 或 Paramiko 执行各角色的命令与文件传输。本机模式下不使用。

VirtuosoClient works with any TCP endpoint (SSH tunnel, VPN, LAN or local), and each profile manages its own tunnel to a separate server. To see the raw mechanism, start with ramic_bridge.il and bridge.py.VirtuosoClient 可连接任何 TCP 端点（SSH 隧道、VPN、局域网或本机），每个配置各自管理到一台服务器的隧道。想看底层机制，从 ramic_bridge.il 和 bridge.py 读起。
