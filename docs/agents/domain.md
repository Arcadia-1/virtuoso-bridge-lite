# Domain docs

This is a single-context repository.

Before exploring a domain, read root `GLOSSARY.md` if present and relevant
decisions in `docs/adr/`. Use glossary terms in interfaces, tests, and tickets.
Proceed when a glossary is absent; create it only when real terms are resolved,
not as an empty placeholder.

Keep accepted decisions in `docs/adr/` with sequential identifiers. Surface
conflicts with an existing ADR explicitly instead of silently overriding it.
